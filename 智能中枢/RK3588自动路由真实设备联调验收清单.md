# RK3588 自动路由真实设备联调验收清单

## 使用范围

本清单用于 RK3588 自动路由开发完成后的真实联调。

- 不使用模拟器；
- 目标设备为真实 `bean_ye_1` 录音豆；
- 默认不执行开始录音和停止录音；
- 只有显式执行安全的 `status.read` 时，才会下发一次真实查询命令；
- 规划阶段不得调用 Bridge，不得发布 MQTT。

## 验收脚本

在项目目录执行：

```bash
cd /Users/jh-05/Documents/ChatGPT/智能中枢系统/智能中枢
python3 tools/verify_rk3588_auto_route.py
```

脚本默认检查：

1. RK3588 健康检查；
2. 硬件网关健康和真实设备目录；
3. RK3588 模式接口；
4. “你好”是否返回 `route=chat`；
5. “你能做什么”是否返回 `route=chat`；
6. “帮我看看录音豆现在的状态”是否生成 `status.read` 计划；
7. “请帮我开始录音”是否只生成 `record.start` 计划；
8. “请帮我停止录音”是否只生成 `record.stop` 计划。

默认脚本不会执行 `record.start`、`record.stop` 或任何真实录音动作。

如果设备已经在线，并且要验证真实状态查询闭环，可以执行：

```bash
python3 tools/verify_rk3588_auto_route.py --execute-status
```

该参数只会执行 `status.read`，不会开始或停止录音。

## 通过标准

### 1. 普通聊天

输入：

```text
你好
你能做什么
```

必须返回：

```json
{
  "route": "chat",
  "reply": "..."
}
```

并且：

- 不返回 `plan_id`；
- 不调用 Bridge；
- 不发布 MQTT；
- 不显示“硬件执行失败”。

### 2. 查询设备

输入：

```text
帮我看看录音豆现在的状态
```

必须返回结构化计划：

```json
{
  "route": "command",
  "status": "planned",
  "plan_id": "plan-xxx",
  "command": {
    "device_id": "bean_ye_1",
    "capability": "status.read",
    "params": {}
  }
}
```

加 `--execute-status` 后，必须能够通过真实 Bridge、HubService 和 MQTT，返回 `succeeded`。

### 3. 开始和停止录音

输入：

```text
请帮我开始录音
请帮我停止录音
```

首次请求只能返回计划：

- `record.start` 或 `record.stop`；
- 有效 `plan_id`；
- `requires_confirmation=true`；
- 不得发布 MQTT；
- 不得改变录音豆状态。

真实开始/停止录音必须由人工单独确认，不在默认验收脚本中执行。

### 4. 澄清问题

输入目标不明确的消息，例如：

```text
帮我处理一下设备
```

应返回：

```json
{
  "route": "clarification",
  "reply": "..."
}
```

不能猜测设备和能力，不能生成硬件计划。

## 失败判定

以下情况均不通过：

- `/api/route` 长时间无响应；
- 聊天消息返回 `timed out` 或“执行失败”；
- 聊天消息生成 `plan_id`；
- 规划阶段调用 Bridge 或发布 MQTT；
- 硬件规划没有 `plan_id`；
- `capability` 使用 `action` 替代；
- 无效 `plan_id` 可以执行；
- 设备离线却返回 `succeeded`；
- 只返回自然语言，调用方无法判断路由类型。

## 注意事项

- 不要为了通过测试临时修改 MQTT 主题；
- 不要把 `chat` 或 `clarification` 当作硬件失败；
- 不要把 `accepted`、`queued`、`running` 当成硬件执行成功；
- 不要在没有人工确认的情况下执行 `record.start` 或 `record.stop`；
- 如果模型服务不可用，RK3588 必须返回明确错误 JSON，不能保持连接无响应。
